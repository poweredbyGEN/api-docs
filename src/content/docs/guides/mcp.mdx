## Connect with OAuth

Add `https://mcp.gen.pro` by URL, then sign in to GEN. OAuth needs no header or key.

- **Claude connector** — add `https://mcp.gen.pro` by URL, then sign in to GEN when the host opens the consent page.
- **ChatGPT connector** — add `https://mcp.gen.pro` by URL as a remote MCP server, then sign in to GEN. The host asks for approval on each write.
- **Other OAuth clients** — add the same URL; the server supports dynamic client registration, authorization code with PKCE, and refresh tokens.

**Verify the connection.** In a new conversation, ask the client to call `gen_discover` with `domain="platform"`, `view="me"`. A 200 proves the credential and transport are working; if the client answers without calling a tool, check that the connector is enabled for that conversation and reconnect.

## Claude Code

```bash
claude mcp add --transport http gen https://mcp.gen.pro
```

Run `/mcp` and sign in to GEN.

## Personal access token (headless and CI)

Clients without OAuth — headless scripts, CI, and custom HTTP clients — authenticate with a personal access token (`gen_pat_...`) sent as a header:

```json
{
  "name": "gen",
  "url": "https://mcp.gen.pro",
  "headers": {
    "Authorization": "Bearer gen_pat_your_key_here"
  }
}
```

Replace `gen_pat_your_key_here` with a GEN API key from **Settings -> API Keys** in [gen.pro](https://gen.pro).

## How the MCP fits with the GEN agent

For Vidsheet editing, MCP forwards typed actions to the GEN API, which owns validation, creation-card behavior, ownership, and persistence. GEN's chat plans over that MCP surface. Natural-language tools such as `gen_ask` (op `chat`) delegate to GEN's agent service; this delegation is separate from the Vidsheet editing path.

- Exact edit → discover supported fields with `gen_discover`, then call `gen_vidsheet_action`. Read saved state with the `gen_discover` sheet view (`include=["full"]` for the whole dump). See [Work with a Vidsheet](/guides/vidsheet-actions/) for draft, generation, and layer examples.
- Fuzzy goal → `gen_ask` (op `chat` to build something, op `ask` for a question about social data). The agent plans, calls the tools, and returns a `run_id` you poll with the `gen_discover` run view. The retired `gen_chat` and `gen_get_run_status` names are hidden compatibility aliases until 2026-10-22.

Older per-target Vidsheet mutation tools are retired; use the action/discovery
workflow above. Job lifecycle remains separate: the `gen_vidsheet_action` op
`stop_generation` stops a job, and op `continue_generation` continues an owned
stopped job using credits and a stable retry key. The retired `gen_stop_generation` and `gen_continue_generation` names are hidden compatibility aliases of `gen_vidsheet_action` until 2026-10-22. See [lifecycle and retry details](/guides/vidsheet-actions/#readback-lifecycle-and-older-integrations).

## Sessions and deploys

`initialize` returns an `Mcp-Session-Id` bound to the running deploy (`<sha12>.<nonce>.<sig>`).

```bash
curl -si https://mcp.gen.pro \
  -H "Authorization: Bearer gen_pat_your_key_here" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-06-18","capabilities":{},"clientInfo":{"name":"my-client","version":"1.0.0"}}}' \
  | grep -i '^mcp-session-id'
```

After a new deploy, a request with an old session id returns HTTP 404 and JSON-RPC error `-32001`.

```json
{"jsonrpc":"2.0","id":2,"error":{"code":-32001,"message":"Session not found ... Send initialize to get the current catalog"}}
```

On 404 with `-32001`, send `initialize` for a new session, then call `tools/list` again. The server advertises `capabilities.tools.listChanged: true`.

The MCP spec requires clients to start a new session on 404. A client that sends no session id stays stateless and is unaffected.

## Errors

Reddit is not supported. A call that names Reddit as a platform or source, or carries a reddit.com URL in any field, is refused before anything is billed. In `gen_analyze`, a request whose only source is a Reddit mention is refused the same way.

```json
{"code":"unsupported_platform","message":"gen_analyze/collect: PLATFORM_UNSUPPORTED: Reddit is not supported (field 'targets.0.target')","field_path":"/actions/0/targets.0.target"}
```

For `gen_vidsheet_action` errors see [Batches and retryable results](/guides/vidsheet-actions/#batches-and-retryable-results).

## Verified writes

Every completed `gen_vidsheet_action` write returns a `verified` block. Report a change only from `verified`.

```json
{"changed":1,"changes":[{"index":0,"action":"update","target":{"kind":"column","vidsheet_id":145435,"id":242367},"verified_by":"read","values":{"title":"HOOK"}}]}
```

See [Verified writes](/guides/vidsheet-actions/#verified-writes) for `unchecked` and `WRITE_NOT_VERIFIED`.

## Hosts and the composer boundary

The public developer surfaces are four hosts, each with one owner:

| Host | Owner | Serves |
|---|---|---|
| `mcp.gen.pro` | gen-mcp-server | The hosted MCP tool surface described on this page; the only public MCP entry point |
| `api.gen.pro` | Rails | The REST API: content engine, Vidsheets, agents, organizations. It owns Vidsheet validation, ownership, creation-card behavior, and persistence |
| `agent.gen.pro` | gen-agentic | Chat, content ideas, research, conversations |
| `agent-core.gen.pro` | agent-core | Agent profile/settings reads and writes, and watchlists |

The composer boundary (GEN-6891): the GEN composer — GEN chat and the Vidsheet editor — is a client of this same surface, not a privileged path. It sends the canonical Rails action envelope, which the MCP relays to `api.gen.pro` verbatim; the MCP does not reconstruct product intent. For Vidsheet edits the agent calls the MCP, never the reverse. The MCP does call `agent.gen.pro` for work that needs judgement or conversation (chat, ideas, research), and Vidsheet ask stays a composer call with Rails as a normal client of the public run API.

## Previously used the local package?

The downloadable `gen-mcp-server` package (PyPI, `uvx gen-mcp-server`) is **retired** and no longer served. Remove it and use the hosted config above. A client already configured with `https://mcp.gen.pro/mcp` keeps working — that path is still accepted.

## What It Can Do

Use your client's `tools/list` for the current tool set and `gen://api-reference` for guidance. For Vidsheet edits, start with [the action and discovery guide](/guides/vidsheet-actions/).

| Area | What your assistant can do |
|---|---|
| **Ask GEN** | Use `gen_ask` (op `ask` or `chat`), `gen_analyze` (`run_research`), and `gen_content_action` (`generate_ideas`) for natural-language work |
| **Create media** | Generate supported videos, images, songs, and voices; final-video rendering is unavailable through hosted MCP |
| **Build Vidsheets** | Read a sheet with the `gen_discover` sheet view, discover card/settings schemas with `gen_discover`, and use `gen_vidsheet_action` for supported structure, drafts, media, and generation |
| **Manage assets** | List libraries, create direct uploads, import media from URLs, rename assets, and delete assets |
| **Run strategy workflows** | Create content ideas, query watchlists, research trends, and manage recurring jobs |
| **Publish** | Connect social accounts, schedule posts, update schedules, edit supported metadata on published posts, and remove scheduled posts |
| **Manage characters** | Use `gen_characters` to list, create, copy, and rename characters, add looks, and make talking characters. The retired `gen_avatars` name still works and points to `gen_characters` |
| **Manage account data** | List agents, workspaces, organizations, API keys, credit balance, usage, and plans |

## Credits and x402

GEN MCP tools use workspace credits for paid generation, research, voice, and song work. Saving a Vidsheet draft or changing its properties does not start generation. Check balance with the `gen_discover` billing views (`balance`, `usage`, `plans`) and estimate paid jobs with `gen_discover` too — the retired `gen_get_credit_balance`, `gen_estimate_job`, and `gen_list_credit_plans` names are compatibility aliases until 2026-10-22.

To add credits:

- For Stripe, read the plans with `gen_discover` domain=billing view=plans, then call `gen_billing_action` action `buy_credits`.
- For USDC via x402, use `gen_billing_action` action `create_x402_credit_purchase`, then
  action `settle_x402_credit_purchase` with the signed payment.

When a paid tool cannot run because the workspace lacks credits, MCP returns a
structured result with `status: "payment_required"`, `status_code: 402`,
`funding_error_kind: "out_of_credits"`, Stripe and x402 `payment_options`, and
the original call under `retry`. This is not a completed operation. Show the
payment choices and obtain approval; after payment succeeds, retry the same MCP
tool once with the same arguments. MCP never purchases credits automatically.

The x402 quote lists every configured network when you omit `network`. Present
those choices instead of assuming one chain. See [Credits](/step-5-export/credits/)
for signing and settlement details.

Workspace funding wallets are backend infrastructure for settlement and sweeping. MCP clients should present the returned payment methods, not ask users to hunt for hidden workspace wallets.

The hosted server is the official GEN MCP — every client connects to `https://mcp.gen.pro`.
